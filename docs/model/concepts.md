# 모델을 읽기 위한 개념

상태: 현재 공통 설명 · 구현 세부는 기능별 문서 참조

수식은 버스 좌석이 어떻게 변하는지를 짧게 적는 도구다. 이 문서는 기호를 외우게 하기보다, 좌석 관측으로 무엇을 알 수 있고 무엇은 끝내 알 수 없는지 설명한다.

기호 해독부터 확률·통계 용어, 전체 수식과 숫자 대입 예시까지 이어서 보려면 [수학 입문서](mathematical-primer.md)를 읽는다.

## 먼저 구분할 세 가지

### 계산할 수 있는 값

입력만 있으면 하나의 답이 나오는 값이다. 예를 들어 버스가 12석으로 들어와 7석으로 나갔다면 좌석은 5석 줄었다.

### 추정하는 값

정답을 직접 보지는 못하지만 여러 관측을 겹치면 범위를 좁힐 수 있다. 정류장별 평소 순수요와 도착 좌석 분포가 여기에 속한다.

### 식별할 수 없는 값

자료를 더 모아도 현재 관측만으로는 답이 하나로 정해지지 않는 값이다. 좌석이 5석 줄었다고 해서 “5명 탑승, 0명 하차”와 “10명 탑승, 5명 하차”를 가를 수는 없다. 두 상황은 좌석 기록이 완전히 같다.

식별할 수 없는 값을 그럴듯한 숫자 하나로 채우지 않는 것이 이 모델의 중요한 원칙이다.

## 좌석 장부

정류장 하나에서 다음 기호를 쓴다.

| 기호 | 뜻 |
|---|---|
| `S⁻` | 승하차가 시작되기 직전의 빈 좌석 |
| `S⁺` | 승하차가 끝난 뒤의 빈 좌석 |
| `A` | 내린 사람 수 |
| `B` | 탄 사람 수 |
| `N = B - A` | 순수요. 양수면 좌석이 줄고 음수면 좌석이 늘어남 |
| `C` | 차량 좌석 정원 |

좌석 보존식은 다음과 같다.

```text
S⁺ = clamp(S⁻ - N, 0, C)
```

여기서 `C`는 개념식에 쓰는 해당 차량의 실제 좌석 정원이다. 현재 구현은 차량별 `C`를 알지 못해 모든 차량의 상태 공간을 0~80석으로 고정한다. 구현의 80은 계산을 위한 상한일 뿐 실제 정원을 관측하거나 추정한 값이 아니다.

순수요가 6명이면 좌석이 6석 줄고, 순수요가 -4명이면 4석 늘어난다. `clamp`는 결과가 0석보다 작거나 정원보다 커지지 않게 자르는 연산이다.

예를 들어 20석으로 들어온 버스에서 3명이 내리고 8명이 타면 순수요는 `8 - 3 = 5`다. 출발 좌석은 `20 - 5 = 15석`이다.

## 검열: 0석 뒤에서 사라지는 사람

20석에서 순수요가 25명이어도 API에는 0석만 남는다. 순수요가 40명이어도 똑같이 0석이다.

```text
S⁺ = 0  →  N은 최소 S⁻ 이상
```

0석은 “수요가 정확히 몇 명이었다”는 관측이 아니라 “이만큼 이상이었다”는 하한이다. 이 상태를 검열이라고 부른다. 만석 뒤에 남은 사람은 좌석 기록에 더 이상 영향을 주지 않으므로 데이터에서 사라진다.

만석 표본을 단순히 버리면 가장 붐비는 날부터 학습 자료에서 빠진다. 현재 구현은 검열을 완전한 상태공간 모형으로 처리하지 못하고 일부 관측을 제외한다. [v2 설계안](../design/boarding-model-v2.md)은 이 표본을 하한 제약으로 살리는 목표를 설명한다.

## 구간합: 개별 정류장은 안 보이고 합만 보일 때

수집 간격 사이에 버스가 여러 정류장을 지나면 좌석 차이는 그 구간 전체의 순수요 합만 알려 준다.

```text
관측 i의 좌석 감소 Δᵢ = 구간에 포함된 정류장 순수요의 합
```

정류장 세 곳을 지나며 좌석이 9석 줄었다고 하자. 관측 하나만으로는 `3+3+3`, `8+1+0`, `12-2-1`을 가를 수 없다. 하지만 버스마다 관측 구간의 시작과 끝이 다르게 겹치면 연립된 영수증처럼 개별 값을 좁힐 수 있다.

현재 구현은 겹치는 구간의 오차가 가장 작아지는 정류장별 평균을 ridge 회귀로 찾는다. 정보가 부족한 정류장에서 값이 지나치게 커지지 않도록 벌점을 둔다. 계산과 검증은 [좌석 예보](seat-forecast.md)에 설명했다.

## 도착 상태와 출발 상태

같은 “현재 정류장 12번”이라도 좌석 숫자가 승차 전인지 승차 후인지에 따라 수요를 붙일 위치가 한 칸 달라진다.

필드 기록과 조밀 관측을 대조한 결과, GBIS 잔여석은 정류장 도착 상태에 가깝게 취급하는 편이 실제 수요 위치와 맞았다. 따라서 목적 정류장 `m`의 도착 좌석을 계산할 때는 목적지 자체의 승차 수요를 넣지 않고 `m-1`까지 전파한다.

## 분포로 전파하는 이유

정류장별 수요는 매번 같지 않다. 평균만 차감하면 “예상 3석”처럼 정밀해 보이지만, 실제로 0석이 될 위험을 말하기 어렵다.

현재 코드는 좌석마다 확률을 둔 배열을 사용한다. 정류장을 하나 지날 때마다 그 정류장 수요 분포를 적용하고, 0과 구현 상한 80에서 잘린 확률까지 다음 정류장으로 넘긴다.

```text
현재 좌석 분포
  → 다음 정류장 순수요 적용
  → 0~정원 범위로 정리
  → 그다음 정류장으로 전달
```

이 분포에서 평균 좌석, 하위·상위 분위수, 만석 확률을 계산한다.

## 대기열의 해소 사건

입석이 없는 버스가 좌석을 남기고 떠났다면, 그 순간 기다리던 사람은 모두 탈 수 있었다고 본다. 이때 대기열은 0으로 돌아간다.

```text
좌석을 남기고 출발  →  대기열 해소 시점
```

두 해소 시점 사이에 버스가 태운 총인원을 구하면 그 구간에 들어온 사람의 평균 속도 `λ`를 역산할 수 있다.

```text
λ = 두 해소 시점 사이의 총 탑승 / 경과 시간
```

같은 구간에서 구한 λ를 같은 구간에 다시 쓰면 사후 복원이다. 미래에 쓰려면 다른 날에도 비슷한 λ가 나와야 한다. 현재 화면은 일부 정류장에 고정 λ를 사용하지만 날짜 간 안정성이 충분히 확인되지 않았다. 자세한 한계는 [대기 범위](queue-estimation.md)에 있다.

## 예측을 평가하는 세 가지 숫자

### MAE

예상 좌석과 실제 좌석 차이의 절댓값 평균이다. MAE가 4라면 평균적으로 약 4석 틀렸다는 뜻이다. 과대예측과 과소예측이 서로 상쇄되지 않는다.

### Brier score

만석 확률의 품질을 재는 점수다.

```text
(예측 확률 - 실제 결과)²
```

실제 만석이면 결과는 1, 아니면 0이다. 낮을수록 좋다. 0.8 확률로 만석이라고 했는데 실제 만석이면 `(0.8-1)² = 0.04`다.

### 예측구간 포함률

“실제 좌석이 이 범위 안에 있을 것”이라고 낸 구간이 실제값을 얼마나 자주 포함했는지 센다. 목표가 80%인데 실제 포함률이 75%라면 구간이 실제 변동보다 좁아 자신만만한 상태다.

## 날짜 순서로 시험하기

같은 날 자료를 학습과 시험에 섞으면 그날의 혼잡을 미리 본 셈이 된다. 그래서 날짜 순서를 지킨다.

```text
1~n일로 학습 → n+1일 예측
1~n+1일로 학습 → n+2일 예측
```

이 방식을 rolling-origin 평가라고 한다. 현재 연구 도구는 `research/backtest/src/backtest.ts`에서 실행한다.

## 자주 생기는 오해

1. 좌석이 5석 줄었다고 5명이 탔다고 단정할 수 없다. 하차가 섞였을 수 있다.
2. 관측이 없다는 말과 수요가 0이라는 말은 다르다.
3. 만석 표본은 값이 없는 표본이 아니라 하한을 주는 표본이다.
4. 구간합 지표가 같아도 정류장별 수요 위치는 다를 수 있다.
5. 사후 복원이 맞았다고 미래 대기열 예측까지 검증된 것은 아니다.
6. 선택하지 않은 정류장에서 실제로 탔을 결과는 관측되지 않는다.

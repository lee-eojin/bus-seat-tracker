# 좌석 예보는 어떻게 계산되는가

좌석 예보는 **지금 보이는 버스가 내가 탈 정류장에 왔을 때 몇 석 정도 남아 있을지** 계산한다. 현재 차량의 잔여석을 출발점으로 삼고, 앞으로 지날 정류장의 평소 좌석 증감을 차례로 반영한다.

이 예보가 직접 답하지 못하는 것도 있다. 정류장에 몇 명이 기다리는지, 아직 화면에 나타나지 않은 버스가 언제 투입될지, 내가 줄의 몇 번째인지까지는 알 수 없다. 화면의 `여유·빠듯·어려움` 판정은 좌석 예보에 다른 신호를 더한 결과이며, 판정 규칙은 [탑승 판정](./boarding-verdict.md)에서 따로 설명한다.

## 먼저 알아둘 현재 상태

| 구분 | 현재 상태 |
|---|---|
| 하류 정류장 도착 좌석의 평균 예보 | 구현되어 화면에서 사용 중 |
| 좌석이 남을 확률 계산 | 구현되어 있으나 화면의 주된 출력은 아님 |
| 표본 부족 표시 | 구현되어 화면에 `표본 적음`으로 표시 |
| 과거 날짜 rolling-origin 백테스트 | 구현됨 |
| 실제로 배포된 예보의 사후 채점 | 채점 도구는 구현됐지만, 최신 성적표는 저장소에 없음 |
| 만석 때문에 사라진 초과 수요 보정 | 미구현 |
| 차량별 실제 정원과 실제 이동 시간 반영 | 미구현 |
| 아직 관측되지 않은 중간 투입 차량 예측 | 미구현 |

따라서 현재 값은 운영 화면에 연결된 **검증 중인 추정치**다. 과거 검증 결과는 모델의 방향을 뒷받침하지만, 모든 날짜와 정류장에서 같은 오차를 보장하지는 않는다.

## 입력

예보 한 건을 계산하려면 다음 값이 필요하다.

1. 현재 버스의 정류장 순번과 잔여석
2. 진행 방향에 있는 정류장 순서
3. 노선별 순수요 프로파일
4. 현재 시각과 평일·주말 구분
5. 화면 데이터 생성 시점의 최근 90분 조밀 관측에서 얻은 만석 연속 횟수

이 가운데 좌석 전파 자체가 직접 쓰는 값은 1~4다. 만석 연속 횟수는 좌석 수를 바꾸지 않고, 그 좌석을 어떻게 해석할지 결정하는 탑승 판정에서 사용한다. 실시간 API는 차량 위치와 좌석만 갱신하므로 이 횟수는 다음 화면 데이터 발행 전까지 그대로다.

### 순수요의 뜻

정류장 `k`의 순수요를 `N_k`라고 쓰면 다음과 같다.

```text
N_k = 승차 인원 - 하차 인원
```

순수요가 5라면 잔여석이 대략 5석 줄고, -3이라면 하차가 승차보다 많아 잔여석이 대략 3석 늘어난다는 뜻이다. 이 값은 정류장에 줄 선 전체 인원과 다르다. 버스가 만차면 기다리던 사람이 더 많아도 실제로 탄 사람만 좌석 변화에 남는다.

프로파일은 다음 세 축으로 나뉜다.

- 정류장 순번
- 30분 시간 버킷: 하루 48개
- 평일 또는 주말

요일별 프로파일이나 방학·휴가철 추세는 아직 따로 두지 않는다.

## 프로파일을 만드는 과정

### 1. 차량 관측을 운행 단위로 나눈다

수집한 스냅샷을 차량별 시간순 관측으로 묶는다. 정류장 순번이 뒤로 돌아가거나 관측 사이가 45분을 초과하면 새로운 운행으로 나눈다. 회차 뒤 운행과 차고지 대기를 한 운행으로 잘못 잇지 않기 위한 기준이다.

다음 관측은 프로파일 학습에서 쓰지 않는다.

- 차량 식별자나 정류장 순번이 없는 관측
- 잔여석이 없거나 음수인 관측
- 같은 운행 안에서도 정류장 순번이 늘지 않은 관측쌍
- 두 관측 사이가 90분을 넘는 관측쌍

45분 초과는 운행을 나누는 기준이고, 90분은 한 운행 안에서 좌석 차분을 학습에 쓸 수 있는 최대 간격이다. 두 기준의 역할이 다르다.

### 2. 좌석 차분을 구간합으로 읽는다

현재 구현은 API의 잔여석을 정류장 **도착 후, 승차 반영 전 상태에 가깝다**고 본다. 정류장 `a`에서 본 좌석과 하류 정류장 `b`에서 본 좌석의 차이는 다음 구간의 순수요 합으로 귀속한다.

```text
관측값: Δ = seats(a) - seats(b)
귀속 구간: a, a+1, ..., b-1
관측 방정식: Δ = N_a + N_(a+1) + ... + N_(b-1)
```

예전 방식은 `Δ`를 구간 안 정류장 수로 똑같이 나눴다. 현재 배포 모델은 그렇게 나누지 않는다. 여러 운행에서 서로 다르게 겹친 구간합을 모아 정류장별 평균과 분산을 역산한다.

### 3. 겹치는 구간합에서 정류장별 값을 역산한다

관측쌍은 하류 관측 `b`의 30분 버킷과 평일·주말 값에 귀속한다. 이렇게 같은 그룹에 모인 쌍으로 정류장별 평균 순수요 `μ_k`를 구하며, 아래 손실이 작아지도록 좌표하강을 사용한다.

```text
Σ_i (Δ_i - Σ_(k in span_i) μ_k)^2 + ridge × Σ_k μ_k^2
```

현재 ridge 값은 1이다. 최대 200번 훑되, 한 번의 최대 변화가 `1e-9`보다 작아지면 일찍 끝낸다. 구간 경계가 여러 형태로 겹칠수록 각 정류장의 값을 나눠 볼 근거가 생긴다. 모든 구간이 똑같이 겹치면 추가 정보가 없으므로 해는 균등 배분에 가까워진다.

분산도 같은 방식으로 복원한다. 먼저 평균으로 설명하지 못한 구간별 잔차의 제곱을 구한 뒤, 그 제곱합을 정류장별 비음수 값으로 다시 역산한다.

### 4. 만석이 낀 구간은 수치 학습에서 뺀다

관측쌍의 시작이나 끝이 0석이면 실제 수요가 좌석 수보다 컸을 수 있다. 예를 들어 4석에서 0석으로 줄었어도 수요가 4명인지 20명인지 좌석만으로는 알 수 없다. 현재 구현은 이런 구간을 평균·분산 계산에서 빼고 `censoredWeight`에만 기록한다.

이 선택은 거짓 숫자를 학습하지 않는 대신, 혼잡한 정류장의 수요를 낮게 추정하는 방향으로 작용한다. 검열 표본을 하한으로 활용하는 보정은 아직 구현되지 않았다.

## 예보 계산

프로파일을 만들었다면 화면은 현재 버스부터 하류 정류장까지 좌석의 **확률분포**를 전파한다. 평균 수요만 계속 빼는 계산이 아니다.

### 1. 시작 분포를 만든다

현재 잔여석이 `S`라면 `S`석일 확률을 1로 둔다.

```text
P(seats = S) = 1
```

상태 공간은 0~80석이다. 3330 노선에서 44석을 넘는 2층버스가 관측됐기 때문에 일반 버스 정원 44석을 상한으로 쓰지 않는다. 다만 80은 넉넉하게 잡은 공통 계산 상한일 뿐, 개념식의 차량 정원 `C`나 차량별 실제 정원이 아니다. 80보다 큰 입력은 80으로 잘린다.

### 2. 현재 정류장의 수요부터 반영한다

화면에 보이는 좌석은 현재 정류장 도착 상태로 간주한다. 따라서 바로 다음 정류장의 도착 좌석을 구하려면 **현재 정류장에서 발생할 승하차부터** 반영해야 한다.

이 순서를 빼먹으면 수요가 큰 정류장의 영향이 한 정거장 뒤로 밀린다. 2026-07-24 범계역 실측이 이 오프셋을 찾는 근거가 됐다.

### 3. 정류장마다 순수요 분포를 적용한다

정류장별 순수요는 평균 `μ`, 표준편차 `σ`의 정규분포로 근사한 뒤 정수 인원 확률로 바꾼다. `μ ± 3.5σ` 안의 정수만 사용하고, 확률이 `0.0001` 이하인 항은 버린 뒤 남은 확률을 다시 합계 1로 맞춘다.

좌석이 `s`이고 순수요가 `d`라면 다음 좌석은 다음처럼 제한한다.

```text
nextSeats = min(80, max(0, s - d))
```

수요가 좌석보다 많아도 잔여석은 음수가 되지 않는다. 하차가 더 많아 순수요가 음수라면 좌석은 늘지만 80을 넘지 않는다.

### 4. 프로파일 표본이 얇으면 이웃 시간대를 합친다

`netDemandAt`은 정확한 30분 셀의 유효 가중치가 1보다 작으면 같은 평일·주말 그룹의 바로 전·다음 30분 셀을 함께 더한다. 그래도 유효 가중치가 없으면 다음 기본값을 쓴다.

```text
mean = 0
sd = 3
lowConfidence = true
```

표본이 있을 때도 분산에는 최소 1을 둔다. 합친 뒤 유효 가중치가 1보다 작거나, 검열 가중치가 유효 가중치의 절반보다 크면 저신뢰 셀로 본다. 저신뢰 셀은 표준편차에 1을 더한다.

한 번이라도 저신뢰 셀을 통과한 하류 예보는 계속 저신뢰로 남는다. 화면에서 `표본 적음`이 붙는 이유다.

### 5. 예상 도착 시각의 버킷을 고른다

현재 구현은 정류장 하나를 이동하는 데 2분이 걸린다고 가정한다.

```text
예상 경과 시간 = 앞에 남은 정류장 수 × 2분
```

이 시간만큼 현재 시각을 앞으로 옮긴 뒤 해당 30분 버킷과 평일·주말 그룹을 고른다. 실제 교통 상황이나 정류장별 이동 시간은 반영하지 않는다.

이 버킷 선택은 화면과 발행 시점 예측 로그의 동작이다. rolling-origin 백테스트는 관측된 도착점의 30분 버킷 하나를 시작점부터 도착점까지 모든 정류장에 사용한다. 두 실행 경로가 공유하는 것은 프로파일과 분포 전파 함수이며, 시간 버킷 조립까지 동일하지는 않다.

## 출력

정류장 하나에 대해 내부적으로 다음 값을 만든다.

| 값 | 뜻 |
|---|---|
| `arrivalMean` | 그 정류장에서 승하차가 일어나기 전 예상 잔여석의 평균 |
| `seatAvailableProbability` | 그 정류장의 수요까지 처리한 뒤 1석 이상 남을 확률 |
| `lowConfidence` | 현재 위치부터 대상 정류장까지 저신뢰 셀을 하나라도 지났는지 |
| `verdict` | `여유·빠듯·어려움` 판정 |
| `streakKnown` | 해당 정류장의 만석 연속 횟수를 실제로 관측했는지 |

`seatAvailableProbability`는 개인의 탑승 확률이 아니다. 현재 계산은 줄에서 내 앞에 몇 명이 있는지 모르며, 해당 정류장의 집계 수요를 처리한 뒤 좌석이 남는지를 본다. 개인에게 보여 주는 최종 결론은 별도의 탑승 판정을 우선한다.

화면은 대상 정류장보다 위에 있는 차량 가운데 정류장 순번이 가장 큰 차량, 즉 가장 가까운 접근 차량을 고른다. 미정차·경유 지점은 수요 전파 경로에는 포함하지만, 사람이 탈 수 없으므로 예보 배지와 길찾기 대상에서는 제외한다.

## 계산 예시

다음은 계산 순서를 보여 주기 위한 단순화한 예다. 실제 계산에서는 각 단계가 한 숫자가 아니라 0~80석 확률분포다.

```text
현재 위치: seq 53
현재 잔여석: 20석
현재 정류장 순수요 평균: 4명
다음 정류장 순수요 평균: 3명
그다음 정류장 순수요 평균: -2명
```

1. 시작 분포를 20석에 둔다.
2. seq 53 승하차를 반영하면 다음 정류장 도착 평균은 대략 16석이 된다.
3. 다음 정류장의 도착값 16석을 먼저 기록한 뒤, 그 정류장 순수요 3명을 반영한다.
4. 그다음 정류장 도착 평균은 대략 13석이 된다.
5. 그 정류장에서 하차가 더 많아 순수요가 -2라면 이후 좌석은 다시 늘어날 수 있다.

실데이터 사례도 있다. 2026-07-24 3330 노선에서 seq53 도착 55석으로 관측된 버스의 문화의거리 도착 좌석은 현장에서 24석이었다. 당시 검증 데이터로 계산한 결과는 다음과 같았다.

| 모델 | 예상 도착 좌석 |
|---|---:|
| 과거 균등 배분·기존 귀속 | 48.9석 |
| 현재 방식인 구간합 역산·도착 귀속 | 40.5석, 10~90% 구간 32~49석 |

현재 방식이 범계역의 큰 승차 수요를 제 위치에 반영해 8석 넘게 교정했지만, 실측 24석과는 여전히 차이가 컸다. 직전 만석 뒤 대기자가 남아 있었을 가능성과 만석 검열처럼 프로파일에 담기지 않은 요인이 있다. 이 한 사례만으로 오차의 원인을 하나로 정할 수는 없다.

## 검증 근거

### 과거 데이터 재현 백테스트

`research/backtest/src/backtest.ts`는 날짜를 하나씩 시험일로 두고, 그 이전 날짜만 학습에 사용한다. 같은 운행에서 앞 정류장의 좌석으로 하류 정류장의 실제 좌석을 예측하며, 다음 지표를 낸다.

이 백테스트는 실제 하류 관측의 도착 버킷을 알고 그 버킷으로 구간 전체 수요를 조회한다. 화면처럼 정류장당 2분으로 미래 버킷을 추정하지 않으므로, 아래 수치는 프로파일과 좌석 전파의 과거 재현 성능을 평가하지만 화면의 이동 시간 가정까지 검증하지는 않는다.

- 도착 좌석 평균절대오차(MAE)
- 만석 확률 Brier score
- 10~90% 예측구간 포함률
- 1~2, 3~5, 6개 이상 정류장 지평별 오차

2026-07-20~24 평일 4개 폴드, 관측쌍 6,480건을 합친 당시 결과는 다음과 같았다.

| 지표 | 좌석 유지 기준선 | 균등 배분 | 구간합 역산 |
|---|---:|---:|---:|
| 전체 MAE | 7.04석 | 4.14석 | 4.19석 |
| 6정류장 이상 MAE | 7.39석 | 4.11석 | 3.93석 |
| 만석 Brier | 0.0824 | 0.0434 | 0.0462 |
| 10~90% 구간 포함률 | - | 72.1% | 74.9% |

구간합 역산은 전체 MAE에서 균등 배분보다 근소하게 나빴고, 긴 지평과 정류장별 수요 위치에서는 나았다. 목표 80%였던 예측구간 포함률도 74.9%에 그쳤다. 한 지표만 골라 “검증 완료”라고 말할 수 없는 결과다.

상세 실험과 범계역 현장 기록은 [2026-07-24 좌석 예보 검증](../research/2026-07-24-seat-forecast-validation.md)에 남아 있다.

### 합성 데이터 검증

정류장 하나에만 큰 수요 25명을 심은 합성 데이터에서 균등 배분은 해당 정류장을 9.4명으로 뭉갰고, 구간합 역산은 23.7명으로 복원했다. 역산기가 서로 어긋난 구간 경계에서 국소 수요를 되찾을 수 있는지는 이 실험으로 확인했다.

### 실제 배포 예보 채점

`research/backtest/src/score-predictions.ts`는 배포 시점에 남긴 예보와 이후 실제 관측을 맞춘다. 90분 안에 같은 차량이 대상 정류장에서 관측돼야 채점하며, 차량이 대상 정류장을 건너뛴 채 잡히면 그 예보는 미대조로 남긴다.

발행 예측 로그는 화면과 마찬가지로 정류장당 2분을 더해 시간 버킷을 고른다. 따라서 이 채점이 쌓여야 rolling-origin 백테스트가 보지 않는 배포 경로의 시간 버킷 오차까지 알 수 있다.

다만 로그는 발행 시각의 하류 1·3·6정류장을 기록하며, 수요 전파 경로에 있는 미정차 지점도 포함한다. 화면은 사용자가 연 시각에 다시 계산해 미정차 지점을 숨기고 만석 연속 수까지 반영한 `verdict`를 보여 주지만, 로그에는 이 판정이 없다. 라이브 채점의 MAE와 Brier score는 좌석 예보를 평가하는 지표이지 화면의 `여유·빠듯·어려움` 판정 정확도가 아니다.

이 도구는 다음을 따로 보고한다.

- 좌석 MAE와 편향
- 좌석이 남을 확률의 Brier score
- 예보와 실제 관측의 대조율
- 더 최신 관측이 있었는데 낡은 근거로 발행한 횟수
- 수집 공백

도구가 있다는 사실과 최근 성능이 좋다는 주장은 다르다. 현재 저장소에는 최신 예측 로그나 누적 성적표가 없으므로, 운영 중 정확도가 위 표와 같다고 확인할 근거는 없다.

## 알려진 한계

1. **만석 검열을 보정하지 않는다.** 0석이 낀 관측쌍을 수치 학습에서 빼므로 가장 혼잡한 정류장의 수요가 작게 학습될 수 있다.
2. **이미 보이는 차량만 예보한다.** 노선 중간에서 새로 투입될 버스는 현재 차량 집합에 없어서 계산할 수 없다.
3. **차량별 정원을 모른다.** 모든 차량에 80석 상태 공간을 쓰며, 실제 차량의 좌석 수를 상한으로 사용하지 않는다.
4. **이동 시간을 정류장당 2분으로 고정한다.** 정체, 전용차로, 긴 무정차 구간을 구분하지 않는다. 시간 버킷 경계 부근에서는 잘못된 버킷을 고를 수 있다.
5. **30분·평일/주말 평균이다.** 요일, 방학, 날씨, 행사, 배차 간격, 앞차 만석 뒤 대기가 남았는지를 직접 설명하지 않는다.
6. **정류장별 순수요를 독립으로 다룬다.** 같은 통근 흐름에서 생기는 정류장 간 상관을 분포 전파에 넣지 않는다.
7. **정규분포 근사다.** 실제 수요의 비대칭과 긴 꼬리, 한 번에 몰리는 단체 승객을 잘 표현하지 못할 수 있다.
8. **저신뢰 표시는 정성적이다.** `weight < 1`과 검열 비중으로만 정하며, 예보가 몇 석 틀릴지를 직접 보장하지 않는다.
9. **현장 검증이 적다.** 귀속 규약을 가른 핵심 근거는 2026-07-24의 한 현장 사례와 이후 조밀 관측이다.
10. **API 값은 정차 중에도 바뀐다.** 한 번의 스냅샷이 항상 도착 또는 출발 상태라고 보장되지 않는다. 현재 모델은 장기 예보에서 도착 상태로 근사하고, 조밀 관측 연구에서는 같은 정류장의 첫 값과 마지막 값을 따로 읽는다.
11. **rolling-origin 백테스트와 화면의 시간 버킷 선택이 다르다.** 백테스트는 실제 도착 버킷을 알고 쓰지만 화면은 정류장당 2분으로 추정한다. 고정된 과거 MAE만으로 화면 경로 전체의 오차를 말할 수 없다.

## 아직 구현하지 않은 개선 방향

현재 코드에 없는 항목은 다음과 같다. 설계 아이디어를 현재 동작으로 오해하지 않도록 구분한다.

- 만석 관측을 “수요가 최소 몇 명이었다”는 하한으로 넣는 검열 보정
- 조밀 관측에서 도착·출발 좌석을 직접 읽어 만든 정류장별 프로파일
- 차량 종류별 실제 정원
- 정류장 구간별 실측 이동 시간과 도착 시각 분포
- 배차 간격과 앞차 만석 뒤 남아 있을 수 있는 대기 수요를 포함한 상태 변수
- 중간 투입 차량의 등장 시각을 추정하는 birth process
- 날짜별·지평별 운영 성적표를 자동 보관하고, 기준선을 넘지 못하면 예보를 숨기는 게이트

## 재현 명령

비공개 수집 데이터 디렉터리가 있어야 실제 수치가 나온다.

```bash
# 과거 날짜를 순서대로 학습·시험하는 백테스트
npm run backtest -- --data-dir=/path/to/private-data --json=/tmp/seat-scorecard.json

# 특정 날짜에 실제로 발행했던 예보 채점
npm run score -- \
  --data-dir=/path/to/private-data \
  --predictions-dir=/path/to/private-predictions \
  --date=2026-08-04 \
  --json=/tmp/live-score.json
```

백테스트 결과를 읽을 때는 전체 평균만 보지 말고 날짜별 폴드, 예측 지평, 실제 만석 건수, 예측구간 포함률을 함께 봐야 한다. 표본이 적거나 진행 중인 날짜는 전체 평균을 쉽게 흔든다.
